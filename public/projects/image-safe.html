Image Safe — a passcode-locked photo vault, in a browser.

My first-year Sentinel Programme project, and one of the first interactive things I ever built. A tiny web app that lets you drop in a photo, lock it behind a numeric passcode entered on an on-screen keypad, and unlock it again — borrowing the metaphor of a hotel-room safe.

The concept

Year 1 of Sentinel was about getting fluent with the basics — JavaScript, the DOM, and the idea that even a few lines of code can produce something tangibly useful. I leaned into the safe metaphor: a numeric keypad, a lock button, an unlock button, and a single photo slot that only reveals its contents when you enter the right code.

One photo, one passcode.

Set a numeric code on the keypad, paste a photo URL, hit lock. The photo disappears. To get it back, the code has to match — otherwise the slot stays empty.

How it works

A small finite state machine wrapped around four DOM elements. No backend, no storage — just enough JS to make the metaphor work end-to-end.

01 · INPUT

Image URL + passcode

The user pastes a photo URL (live-previewed in the image slot) and types a numeric passcode by clicking on-screen keypad buttons. A clear button resets the field.

02 · LOCK

Stash the state, hide the photo

Hitting Lock stores the passcode in memory, blanks the image source, clears the inputs, and swaps the button to Unlock.

03 · UNLOCK

Match, then reveal

The user types their code again; if it matches the stored value, the original photo URL is restored to the image element and the safe re-opens. Otherwise nothing happens.

What I took from it

Small project, surprisingly transferable lessons.
